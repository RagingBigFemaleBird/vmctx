vmhome ran the first image's dynamic loader natively under ptrace to a
breakpoint at AT_ENTRY and handed over at _start, so the first image's
relocations, IFUNC choices and every library constructor executed on the
source CPU while exec'd children's ran in the guest -- one process
family, two rules. Cross-machine it surfaced as OpenSSL probing the
Ryzen's SHA-NI and the Intel guest executing sha1msg1 (#UD). Owner's
ruling: develop and gate with the correct architecture first. The
hand-over is now at the post-exec stop (where the vDSO-hiding auxv patch
already lived), the same point exec'd children use; the shortcut stays
behind VMHOME_NATIVE_LOADER=1 as the measured-faster start-up.

vmctx: the browser campaign -- five lifecycle/ordering fixes from netsurf and firefox corpses (AUDIT #33-#37), protocol VMR6

Session 47. links2 runs cross-machine with its window on the AMD box's
own display; netsurf renders cross-machine and 6/6 on loopback on this
build; firefox clears its startup walls on loopback and runs ~20 s into
the coherence residual. Each fix was read from a kept corpse:

#33 The readahead's claim outlived an EEXIST landing: the record stayed
    CLAIM and every guest pull of the page was answered CLAIMING for the
    rest of the run (session 42b's stuck-claim stall; LAN, where
    readahead is on). Settled to the prior state, HOME when the prior
    was THEIRS.

#34 A service task's death by signal never reached the destination
    (netsurf's parent SIGKILLs a helper; firefox's content process
    abort()s): the guest's contexts spun on futex(-EIO) for ever. The
    reply carries the dead task's wait status (VMR6: ended/ended_status)
    and the destination ends that one context on the source's word,
    reporting the source's status home. A first form ended the whole
    address space on one thread's word and mis-read a zombie thread's
    exit_code 0 as SIGKILL: took a live netsurf down; corrected.

#35 The construction repair fired on EFAULT only; a PROT_NONE
    reservation another thread MAP_FIXED'd over answers EACCES from
    TRYFAULT, so firefox's main context died -14 reading a page its own
    thread had just mapped. EACCES repairs too.

#36 The first context stood in for a gone context of ANOTHER address
    space (a forkserver child's thread was answered from the parent's
    mm: "no such address"). ctx0 stands in only when as_of agrees.

#37 An mprotect reply had no construction row, so a sibling's first
    touch of a glibc arena page grown by another thread was
    unrepairable (netsurf's helper thread, every loopback run). PROT
    replies are noted for the REPAIR only -- letting them order vacates
    took netsurf loopback 2/3 -> 0/3 (an mprotect's stamp is unordered
    against another thread's munmap) and is recorded as refuted.

Found, not fixed: the loader and every library constructor run on the
source, so OpenSSL probed the Ryzen's SHA-NI and the Intel guest
executed sha1msg1 (#UD); demo workaround OPENSSL_ia32cap=:~0x20000000,
the fix is handing the first image over at the exec stop.

Harness: runany-x.sh honours VMCTX_SHARED=1 (no global kills; ends only
its own pair) so the cross suite can run beside a demo.

Gates (kernel #181, srcid 7d1715516402 both boxes): loopback suite x3
120/0; progs 68/1 (nodework's known ~1/6 thread-list class) + 3 known
gaps; cross suite 40/0 (all beside the running demo).

Docs: AUDIT §10 #33-#37, HANDOFF §0b (session 47).
