## Architectural CPU state

VMR7 adds full CPU-state payloads on forwarded calls and queries the source's
initial/child state before destination execution begins. Its extended-state
format carries the architectural 576-byte XSAVE legacy region/header, followed
by active component ids, sizes, and bytes. Each local kernel adapter translates
its own CPUID-reported offsets; neither an OS layout nor identical XSAVE offsets
are assumed across machines. Unsupported active components and malformed images
are rejected instead of silently dropped. Capability negotiation and other
existing OS-dependent parts of the protocol still need work.

GETCPU/SETCPU pin the task with scheduler locks, require it to be off CPU and
idle at the service/monitor gate, and perform only kernel-buffer copies while
those locks are held. User copies and allocations happen outside the locks.
Access is serialized against assisted syscall admission. A caller abandoning an
assisted syscall no longer clears the slot while that syscall may still execute.
The worker publishes all results before releasing the slot. The kernel-buffer
FPU regset path skips `vfree(NULL)`, which would assert sleepability while the
scheduler locks are held. Both kernel versions carry these changes in patch
0005; the 7.0.14 patch also exports the previously pending futex declaration.

rows were evicted after 1024 entries, and a partial retirement removed an entire
1 MiB mapping row. The construction store now grows, reuses retired slots, and
aborts on allocation failure rather than dropping live metadata. Retirement
preserves both outside fragments and adjusts their object offsets. Replay is
clipped at newer submappings, including opaque non-replayable constructions;
an older exact-range reply cannot replace a newer recorded row. Discards retain
mapping metadata. Exec retires the previous image's construction rows.

## Source-described execution effects (hardware validation pending)

VMR9 separates transport operations from opaque guest call identifiers. The
previous wire format routed guest call 0x1000 as OP_START. OP_EXECUTE now carries
the identifier separately; OP_PREPARE lets the source choose required page-loan
settlement without a Linux clone-number switch in the executor. This adds a
preparation round trip per forwarded call. The existing settlement algorithm and
its concurrency limitations still require review; the extra message does not
establish a fork snapshot barrier.

Mapping constructions now carry explicit kind, address, length, architectural
permissions, backing offset, and relocation pairing. The destination mapping
application API receives neither syscall arguments nor its number, and does not
ignore an effect because a syscall failed. Image replacement and child creation
also use source-declared flags. Linux shmat SHM_RDONLY/SHM_EXEC permissions are
translated at the source instead of unconditionally granting read/write. Native
source-adapter and destination malformed-effect controls pass. An added guest
control checks identifiers 0x1000 through 0x1010; its native arm passes, its guest
arm remains pending. The hardware suite now contains 51 cases.

This does not fix the committed-state journal: the source adapter still produces
most constructions from successful calls, partial mprotect and PTE guard changes
are not yet propagated, and sampled sequence numbers do not impose commit order.
Termination still carries a Linux wait status, and source-native death retention
is unresolved. No different-OS compatibility claim follows from these changes.

The destination's syscall-number-based connect, signal-frame, and futex diagnostic
peeks were removed. They were source OS interpretations and could touch memory
outside the guest operation itself. Generic instruction/argument traces remain.
Child startup now fails closed if the source cannot capture its full CPU state;
a zero FS base is no longer treated as evidence of an invalid child frame.

### Recall and shared-page repair

The first destination repair refuses shared-page ABSENT/CLAIMING/error responses
as initialization authority. Its shared-snapshot run exits 98 with both kernel
context and module reference counts zero. It exposes a separate first-touch
defect: a legitimate newly truncated source memfd page is refused by the foreign
shmem read guard and flattened to ABSENT. Logs are in
`logs/audit-20260907/lab/audit-shared-failclosed-1`.

Source patch 0009 introduces thread-owned 64-bit recall tickets. BEGIN pins the
source mm and page-record slot, reserves a recorded remote loan, and releases all
locks before the network request. COMMIT pins the exact source page and orders
its final copy against mapping invalidation; an invalidated ticket returns
ESTALE without writing a replacement mapping. CANCEL and monitor thread exit
release the reservation. Invalidation precedes the old vacate-log deduplication,
so repeated genuine unmaps of the same range cannot hide from a ticket. Local
LAND, TAKE, SERVE and POKE operations participate in the same reservation
exclusion. POKE pins both pages of an unaligned write before copying. Native
fault claim and completion check reservations under the same spinlock as their
record transition; an unlocked busy probe followed by CAS was insufficient.

Source-owned shared shmem reads use the actual source file's native folio lookup,
including EOF, swap and full mapped-tail behavior. They do not permit foreign
execution backing objects to allocate pages. Writable shared-page copies remain
TRANSIT until the destination acknowledges installation. vmhome's explicit
recalls and speculative recall windows use tickets; failed or stale byte
transfers terminate instead of restoring a record or writing bytes through a
reused address.

operations, owner-thread identity, bad user buffers, thread exit, partial writes
across two pages and repeated address reuse on hardware. Its first attempt used
the low-level SERVICE run path, which does not adopt an mm and therefore returns
