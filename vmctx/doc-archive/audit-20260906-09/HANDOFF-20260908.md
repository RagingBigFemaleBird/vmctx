## AMD crash: evidence and implemented candidate repair

Read `vmctx/audit/bad-page-state-20260908.md` first. Full previous-boot journal:
`DBASE/amd201-crash-journal.log`, especially lines 267009–267115.

The new native `take-file-race` regression crashed AMD #201 at monotonic
14580.609034. The competing mapper thread PID 97280 freed a folio with refcount
0, mapcount 0, and a non-null shmem mapping for `memfd:take-file-race` through
munmap / tlb_finish_mmu / folios_put_refs. It then stalled in filemap_get_entry /
shmem_get_folio_gfp, causing an RCU stall and unrelated blocked work. The user
reset the machine. This is a native page-ownership defect, not a CPU mismatch.

Old claim checked `!folio_mapped`, then froze
`folio_expected_ref_count(folio) + 1`. The helper includes a racing mapcount.
A mapper's live reference could therefore authorize a freeze. Release then
recomputed the count and could omit a reference that had disappeared from
mapcount but still needed to be dropped by its owner. No folio lock stabilized
swap-cache membership either. The observed crash is consistent with those
races; the exact instruction interleaving was not captured.

Candidate repair, in both native core versions:

- Refuse VM_SHARED mappings in private TAKE before removing their PTEs.
- For private file-backed pages, resolve native FOLL_WRITE COW and retain the
  actual anonymous result. Existing aliases keep the cache page. Read-only
  private file mappings currently return EBUSY intact; evaluate any resulting
  functional stalls rather than weakening ownership checks.
- Before destructive zap, require an order-zero, non-KSM anonymous folio and
  allocate a kernel snapshot page. Existing split/precheck behavior remains.
- Claim takes `folio_trylock`, waits for writeback, excludes mappings/pins, and
  freezes only the owned GUP ref plus an optional swap-cache ref. Mapping refs
  never enter that count. Drain deferred LRU refs on exact-freeze failure.
- Successful claim retains the folio lock and returns the exact frozen count.
  Release restores that exact number, then unlocks.
- Copy the frozen bytes to the kernel snapshot; unfreeze/unlock before user
  copyout. Retain fail-closed ENOTRECOVERABLE + SIGKILL for destructive failure.
- Unratelimited post-zap failure diagnostic now includes target PID.

Only private TAKE uses this freeze helper. TAKEOBJ/PROTECTOBJ use their separate
folio-lock protocol; their treatment of non-DMA GUP writers remains an audit
concern and was not repaired in this patch.

Regression `vmctx/tests/control/take-file-race.c` now has two concurrent aliases
(MAP_PRIVATE and MAP_SHARED), 1,000 private transfers, a fresh faulting monitor
destination each round, byte checks, and intact-refusal cases for read-only
private/shared mappings. It compiled successfully with sanitized native UAPI
headers. The **expanded** version has not yet run on either candidate.

## Native debugging and syscall tracing remain incomplete

`vmctx/audit/ptrace-repair-design-20260908.md` describes the tracing gap but its
last paragraph predates #65 and should be updated when validated.

Staged native #DB core changes factor `exc_debug_user` work into common native
handling, called from SERVICE without nesting context tracking. Native Linux
chooses ptrace/signals. The exception cause field carries positive DR6 cause
bits (allowed mask 0x1e80f); native #DB error_code is zero. SVM initializes DR6 /
DR7 and reports/reset sticky cause bits. VMX handling changes need the missing
field reads at the top of this handoff. Debug-traps checks TF and ICEBP exact
RIP, si_code, trap number and error code. ptrace-step additionally verifies
PTRACE_GETSIGINFO TRAP_TRACE and DR6.BS after each of twelve stops.

Syscall tracing is **not implemented**. `arch/x86/kernel/vmctx.c` calls
`x64_sys_call` directly, skipping native entry/exit ptrace/seccomp/audit work.
Do not blindly insert full syscall entry/exit wrappers inside SERVICE: they
would repeat context transitions. Source-native work helpers need a correct
admission protocol.

Tracer entry can rewrite syscall identifiers and arguments. Current PREPARE
classifies the incoming call too early. The new ptrace-syscalls regression
rewrites getppid to mmap and fork, then suppresses another call with a custom
return. The source must classify the actual admitted call and the executor
must prepare snapshots before dispatching that call. Source mapping effects
must also use the admitted call. Do not teach the executor Linux numbers.

A design considered native ENTER/COMMIT controls with a per-context frame and
lifetime ticket: install the canonical frame, run native entry work, retain
actual nr/args, return only semantic preparation flags, then COMMIT that admitted
frame without overwriting it from stale executor state. Internal ctx_sys scratch
calls must be distinct and must not consume guest admission or tracing stops.
No such controls or protocol changes have been implemented.

Existing vfork/clone3 rewriting is also incorrect if done after native tracing /
seccomp admission. True vfork needs child publication while its parent is
blocked, with an intermediate child reply, stable ownership leases, and later
parent completion. Do not hide this by rewriting an already-admitted call.
Hardware DR0–3/DR6/DR7/DEBUGCTL transport and asynchronous attach/quiescence are
still absent. Source deferred signal work can see stale canonical frames;
30-second assisted-call deadlines complicate long debugger stops.
